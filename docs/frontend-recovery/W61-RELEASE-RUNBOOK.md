# W61 上线前检查与回滚操作手册（生产 NO-GO）

本手册是独立审批、预发布和回滚的**人工 runbook**；W61 CI 从不执行生产切流、数据库恢复或覆盖 `src/www`。任何真实资金、外部商户、支付生产 URL、生产私钥/Token 都不得进入 GitHub Actions 或测试日志。

**供应商身份核验特别提醒：** 网上名称相似的 `OPay`、`OkePay`、`okepay.biz`、`okepay.info` 文档不能直接证明其和项目的 Go `/payLink`+MD5 协议兼容，**不得猜测一个 URL 作为官方沙箱**；没有供应商书面授权/环境确认之前不执行外部写请求。

### 外部测试准入材料（必须先收齐）

1. 独立测试专用网络/钱包/Token/测试收款地址和允许的 RPC 域名；明确与主网隔离的 chain ID、Token 合约、区块浏览器、区块确认阈值，链上测试必须使用无需真实价值的测试 Token。
2. **官方** OkPay 提供的 hostname、商户测试账号、明确无真实资金的书面沙箱条款、callback 校验规则、供应商订单查询流程、限制速率与过期/退款规则。保密值仅存独立预发布 Secrets，不进仓库。
3. 独立商户沙箱 URL 和可验证的收件系统唯一索引 `X-Epusdt-Delivery-ID + 商户订单号`；独立于 Go 回调服务和数据库。
4. 一次性测试订单号、测试数据清理范围、人工停止开关以及网络层禁止生产域名的出口规则；事前批准后才允许沙箱交易。

### 真实预发布切换（仅供人工流程，W61 不运行）

1. 核对 `master` SHA、Actions 与 NO-GO 表。存在任意 BLOCKED **立即停止**，不执行后续步骤。
2. 在真正的隔离预发布机器上，把原版 `src/www` 静态文件、Go 二进制、配置和 MySQL 5.7 数据库 **单独**生成可恢复快照；用校验和核实快照并确认回滚负责人。不要把秘钥/原始交易内容放进测试报告。
3. 在隔离环境独立启动新 Go 和 Web 副本，禁止生产 RPC/商户/OkPay 出网，所有诊断与提交仅指向隔离数据库；用本手册 G02–G08 的批准测试材料完成交易/回调/刷新/回滚复验。
4. 对比两套前端同一浏览器 origin 与 Service Worker scope，并同时覆盖已缓存旧 bundle、新 bundle、无网及刷新；验证 `manifest.webmanifest`、`registerSW.js`、`sw.js` 与缓存迁移，不允许自动清除真实用户缓存。
5. 按业务独立审批决定是否采用分批流量或版本灰度。W61 没有可自动运行的生产发布入口。

### 预发布故障回退（人工演练流程）

1. **停止新增支付目标选择与创建供应商订单**，但不冒充现有订单已过期或已支付。严禁重复支付/自动补单。
2. 将静态入口切回**已备份且通过 hash 的原版**；Go 数据和 `payment_tx_claim`、`callback_delivery` 账本必须保留，不能直接清库或删除 claim。若需要迁移回退，先 DBA 评估向后兼容性，不能直接运行 `DROP TABLE`。
3. 对所有订单、子单、供应商 ledger 与回调租约执行**只读**对账；对“提交状态未知”情况以 DB 唯一 claim、父子关联和 Delivery ID 为依据，不重放交易或自动发商户回调。
4. 验证旧 PWA bundle 不再从 Service Worker 返回错误版本；必要时在**单独的预发布 origin**用经过审查的手段迁移 SW，不能在生产站点自动 unregister 全局 SW。
5. 在同一隔离环境核验订单仍可读、未发生双重结算、回调唯一标记可重试恢复。记录工单、实际耗时、hash、负责人与签字；真实演练仍为 BLOCKED，直到完成。
